# 影棚布光图编排 · Studio Lighting Planner

> 类型：前端 Web 应用（纯前端）｜难度：★★★｜技术栈：**React 18 + TypeScript（严格模式）+ Vite 5**（手写 CSS；路由、导出、持久化均自研，运行时只依赖 react / react-dom）

## 1. 一句话简介
在影棚平面图上摆灯位与道具，实时算出光比、光圈、相对角度与覆盖范围，出图给助理照着搭，也顺手出一张参数表给客户看。

## 2. 真实场景与痛点
- 商业摄影与影棚拍摄靠口头交代灯位：主光在哪、离模特多远、几档功率、什么配件，一句话说不清，助理照错一步整场重来。
- 光比是摄影的基本语言（主光比辅光强几档），但现场没人能手算平方反比，只能凭经验反复试。
- 灯的距离一改，光圈就变；模特一转，每盏灯的相对角度全变，靠脑子记不住。
- 换一套布光（伦勃朗、蝴蝶光、白底三灯）要重新摆一遍，希望有现成模板；搭完还想留档、下次直接调出来。
- 现有工具要么是通用绘图软件（画完不会算），要么是手机测光 App（只能测一个点，出不了图）。

## 3. 目标用户
- 影棚摄影师、灯光师、摄影助理。
- 器材租赁公司与影棚运营方（给客户出布光方案）。
- 摄影教学与实训（教师出题、学生照着搭）。

## 4. 核心功能（MVP）
1. **平面图画布**：可调尺寸的影棚平面图（默认 6m × 5m），半米网格；拖入、拖动、旋转灯位与道具；方向键微调 5cm（Shift 加速到 20cm），`[` `]` 每次转 5°，`Delete` 删除。
2. **元素库**：相机 / 模特；闪光灯与持续灯；柔光箱、反光伞、雷达罩、裸灯、旗板；反光板、背景纸、旗板道具。灯具有主光、辅光、轮廓光、背景光四种角色，**颜色与形状双编码**（色盲友好）。
3. **光比计算**：按平方反比 `E ∝ 功率占比 / d²` 汇总所有闪光灯在模特处的相对照度，给出主辅光比与 EV 档差，并展示完整计算过程（每盏灯的档位、距模特距离、1/d²、相对照度）。
4. **光圈换算**：按主光闪光指数求推荐光圈 `f = GN × √(ISO/100) × √(功率占比) / d`，同时给出精确值与吸附到常用档后的值；支持按目标光圈反解所需功率档。
5. **角度**：算出每盏灯相对模特朝向的角度、以及相对「相机—模特轴」的角度；模特转向后所有灯的角度随之更新。
6. **覆盖范围**：按配件尺寸与发散角估算光斑尺寸与照度均匀区，可在画布上按「选中灯 / 全部灯 / 隐藏」三态显示。
7. **反光板补光**：按反射效率估算反光板能给暗部补多少档，并计入光比明细。
8. **模板**：内置 8 套经典布光（伦勃朗、蝴蝶光、夹光、三灯白底、静物顶光、环形光、分割光、主播平光），一键载入后继续微调。
9. **持久化**：方案存本地数据库（IndexedDB），改动后自动保存；方案可复制、可导入导出 JSON；设置存 localStorage。
10. **出图**：位图导出（含标题、推荐光圈、图例与参数表）；打印视图可直接另存为 PDF。

## 5. 进阶功能
- 拖动时的实时浮标：显示与模特的平面距离、相对角度与当前光比。
- 灯具参数里的闪光指数表：把常用灯具的 GN 存成表，新建灯时直接挑。
- 单位切换（米 / 英尺）与默认影棚尺寸。
- 持续灯按光通量（lm）或功率（W）估算，并提示快门对持续灯曝光的影响。
- 快门超过常用同步速度时给出提示。

## 8. 关键算法
- **相对照度**：`E ∝ 功率占比 / d²`，`d` 取灯到模特的平面距离并做 0.1m 下限保护（防除零）。参考点：全功率 @1m 记作 1。
- **光圈**：`gnAtStep = GN × √(功率占比)`；`f = gnAtStep × √(ISO/100) / d`；推荐值吸附到常用光圈序列（1、1.1、1.2 … 22）。
- **反解功率档**：由目标光圈反推所需等效 GN，除以全功率 GN 得到精确占比，再取最接近的一档，并回报该档实际达到的光圈。目标超出全功率时钳到最高档。
- **持续灯**：以光通量（lm）为强度来源，只填功率时按 20 lm/W 粗估；`relE = lm / 10000 / d²`；持续灯不参与闪光光比，并给出相对 1/125s 的快门影响档数。
- **角度**：`azimuth = atan2(dy, dx)`（0° 指向 +x），归一到 (−180°, 180°]；相对模特角度 = 方位角（模特→灯）− 模特朝向；相对相机轴角度 = 方位角（模特→灯）− 方位角（模特→相机）。
- **覆盖范围**：`光斑 = 配件尺寸 + 2 × d × tan(发散角 / 2)`；照度均匀区取光斑中心的约 60%。发散角按配件类型取（柔光箱 60°、反光伞 75°、雷达罩 45°、裸灯 55°、旗板 25°）。
- **反光板**：`E_板 ≈ η × max(cosα, 0) / d²`（η 取 0.6），补光档数 `log2(1 + E_板 / E_辅)`；板面几乎背对模特时不给估算。
- **元素夹回房间**：所有坐标夹在 `[0.1, 房间边长 − 0.1]`，调整房间尺寸后灯、道具、模特、相机一起夹回室内。
- **性能**：拖动用逐帧节流，一帧只提交一次位置更新；20 盏灯的拖动帧间隔中位数不超过 20ms。

## 9. 交互与视觉要点
- 角色用颜色 + 形状双编码（主光圆、辅光方、轮廓光三角、背景光菱形），**不依赖颜色单独传达信息**。
- 拖动时浮标跟随指针，显示「距模特距离 · 相对角度 · 光比」；拖动中的灯画一条指向模特的参考虚线。
- 光比面板用大字号，现场举着手机也能读；参数表逐行列出每盏灯，主光与辅光行高亮。
- 覆盖范围示意层不拦截鼠标（否则点不到灯）。
- 窄屏（≤980px）时编辑器改为纵向堆叠，画布在上、面板在下。
- 打印视图单页排布：图在上、参数表在下，表不跨页。

## 10. 验收标准
- 光比：主光 2m、辅光 3m、同功率 → 比值为 2.25 : 1，档差为 log2(2.25)。
- 光圈：闪光指数手工核算 20 组，与公式一致；吸附到常用档的结果稳定；反解功率档可往返（反解出的档位算回光圈与目标一致或在最近档内）。
- 角度：方位角基准正确；模特朝向 −90° 时 45° 侧光算出 −45°，模特转向 90° 后同一盏灯变为 −135°。
- 覆盖范围：三档尺寸随距离与配件变化，取值符合公式。
- 反光板：正对模特时补光档数随距离递减，背对时为无贡献。
- 模板：8 套模板载入后所有元素都在房间内，可算出光比。
- 数据：方案 JSON 导出再导入完全一致（富场景无字段丢失）；坏数据被拒绝。
- 交互：拖入、拖动、旋转、方向键微调、删除都生效；20 盏灯拖动保持流畅（帧间隔中位数 ≤20ms）。
- 持久化：刷新页面后方案仍在，且落在原方案上。
- 出图：位图含标题、推荐光圈、图例与参数表；打印视图的图与表同页。

## 11. 边界（刻意不做）
不做光学仿真（覆盖范围只按标称发散角估算）、不做多机位与视频拍摄、不做器材租赁与报价、不做云端协作与账号体系、不做照片管理。核心只做**「摆位 → 算出来 → 出图」**，避开黑名单中的报表看板、预约系统与电商方向。

**已知实现边界**（写题与验收时按代码现状为准）：
- 覆盖范围当前只算光斑与均匀区两档，暂无外延区。
- 灯到模特的距离只看平面坐标，灯心高度只作展示，未参与光比与光圈。
- 相机焦距只作参数与标签展示，未参与取景范围计算。
- 闪光同步速度在设置里可填，但光比面板的超速提示仍按固定的 1/250s 判断。
- 方案标识与时间字段由本地生成；每次自动保存会重写记录的创建时间。

## 12. 容器化与构建（Docker）

本项目交付**必须能通过 Docker 构建与运行**，验收以容器内运行结果为准。

- **Dockerfile（多阶段）**：`node:20-alpine` + `npm ci && npm run build` → `nginx:1.27-alpine`，只拷 `dist/` 与 `nginx.conf`
- **docker-compose.yml**：服务名 `app-018`，端口 **`8098:80`**，`restart: unless-stopped`；`HEALTHCHECK` 请求 `/healthz`
- **nginx.conf**：SPA 回退 `try_files $uri $uri/ /index.html`；带哈希资源 `immutable`；`index.html` no-cache；gzip（js/css/json/svg）；IPv6 双栈监听
- 无后端依赖：摆位、计算、出图全在浏览器内完成，**断网可用**
- 字体与图标本地打包，禁止外网 CDN

```bash
docker compose up -d --build
curl http://localhost:8098/healthz
docker compose down
```

- **验收**：`http://localhost:8098` 完成「新建方案 → 拖入灯位 → 看到光比与推荐光圈 → 导出图片」；镜像压缩层 < 60MB；刷新后方案仍在（IndexedDB）。
